## 🤖 Gemini

Desenvolver um explorador de arquivos UWP para Xbox exige bibliotecas feitas em **C# puro (.NET Standard / UWP)**, pois o ambiente de sandbox do Xbox impede o uso de wrappers Win32 nativos ou chamadas de API do sistema operacional tradicional.

As bibliotecas mais recomendadas e compatíveis para cada protocolo:


### Bibliotecas Recomendadas por Protocolo

| Protocolo | Biblioteca NuGet | Destaques e Observações |
| --- | --- | --- |
| SMB (SMB2 / SMB3) | SMBLibrary (TalAloni.SMBLibrary) | Implementação 100% C# em nível de socket de SMBv2 e SMBv3. Essencial para redes Windows e NAS locais no UWP. |
| SFTP | SSH.NET (Renci.SshNet) | Padrão da indústria para SSH/SFTP em C#. Muito estável, suporta autenticação por chave e senha. |
| FTP / FTPS | FluentFTP (FluentFTP) | Bastante ativa, suporta FTP e FTPS (TLS/SSL), assíncrona (async/await) e compatível com .NET Standard. |
| WebDAV | WebDav.Client (WebDav.Client) | Wrapper leve sobre HttpClient. Facilita operações como PROPFIND, download, upload e criação de diretórios. |
| NFS | NfsClient (NfsClient) | Suporte a NFSv3 em C# é escasso. O NfsClient atende casos básicos, mas o protocolo exige mais testes no sandbox do UWP. |


### Configurações Críticas no UWP / Xbox

Para que essas bibliotecas consigam abrir conexões de rede no Xbox, adicione as seguintes permissões no seu arquivo **`Package.appxmanifest`**:

XML
```
<Capabilities>
  <Capability Name="internetClient" />
  <Capability Name="internetClientServer" />
  <Capability Name="privateNetworkClientServer" />
</Capabilities>
```


### Dicas de Arquitetura para o Projeto


- **Interface de Abstração Comum:** Crie uma interface base no seu projeto (ex: `IFileSystemProvider`) com métodos assíncronos (`GetFilesAsync`, `DownloadFileAsync`, `CreateFolderAsync`). Isso permite abstrair se o destino é local, SMB ou SFTP.
- **Stream Virtualization:** Como os arquivos remotos podem ser grandes e o Xbox tem limitações de RAM para apps UWP em background, evite carregar arquivos inteiros na memória. Trabalhe sempre com `Stream` para leitura e escrita sob demanda.
- **Políticas de Timeout:** Conexões Wi-Fi no Xbox podem oscilar. Configure timeouts explícitos nas bibliotecas de rede para evitar que a interface do app congele.

## 🤖 Gemini

Para cobrir a grande maioria dos cenários em redes domésticas, servidores de mídia, NAS e ambientes corporativos, estes são os protocolos essenciais organizados por prioridade de uso:


### 1. Essenciais (Cobrem ~90% do uso do dia a dia)


- **SMB / CIFS (Server Message Block)**


- **Uso:** O padrão absoluto em redes locais para Windows, Linux (via Samba) e macOS.
- **Por que ter:** Todo NAS comercial (Synology, QNAP, TrueNAS) vem com SMB ativo por padrão. Se o usuário quiser acessar pastas compartilhadas de um PC Windows ou de um NAS na mesma rede, o SMB é indispensável.
- **SFTP (SSH File Transfer Protocol)**


- **Uso:** Acesso remoto seguro via internet ou redes locais (muito comum em servidores Linux e Seedboxes).
- **Por que ter:** Usa a porta padrão do SSH (22), o que facilita a travessia de roteadores sem precisar abrir várias portas.


### 2. Altamente Recomendados (Mídia e Servidores Pessoais)


- **FTP / FTPS (File Transfer Protocol + SSL/TLS)**


- **Uso:** Transferência tradicional de arquivos e roteadores domésticos que oferecem função NAS via USB.
- **Por que ter:** Embora o FTP puro seja antigo e sem criptografia, muitos roteadores Wi-Fi antigos/básicos ainda usam FTP simples para compartilhar HDs externos na rede local.
- **WebDAV (Web Distributed Authoring and Versioning)**


- **Uso:** Acesso a serviços de nuvem pessoal (Nextcloud, ownCloud) e unidades remota trafegando via HTTP/HTTPS (portas 80/443).
- **Por que ter:** É o protocolo ideal para passar por firewalls restritivos e NATs sem complicação, além de ser a base da maioria das nuvens self-hosted.


### 3. Secundários / Nicho


- **NFS (Network File System)**


- **Uso:** Padrão nativo de redes Unix/Linux de alta performance.
- **Por que ter:** Muito usado por entusiastas para *streaming* de vídeo em altíssima taxa de bits (4K BD-Remux), pois tem menos *overhead* (sobrecarga de cabeçalho) que o SMB em redes locais cabeadas.
- **DLNA / UPnP (Media Server)**


- **Uso:** Apenas leitura e navegação em catálogos de mídia (vídeos, músicas, fotos).
- **Por que ter:** Não é um protocolo de sistema de arquivos tradicional (não permite renomear ou deletar), mas é o padrão que servidores como Plex, Jellyfin e MiniDLNA usam para transmitir mídia na rede sem autenticação pesada.


### Resumo para Escopo de Desenvolvimento

Se a ideia for estruturar o suporte por etapas no projeto, o roteiro mais prático de implementação seria:


1. **Fase 1 (MVP):** SMB + SFTP
2. **Fase 2 (Expandido):** WebDAV + FTP/FTPS
3. **Fase 3 (Avançado):** NFS + Suporte a cliente DLNA
